# MTM 0.5.0-preview.1 — Native permission authority

## Release contract (MTM-014)

This is a preview, not a replacement for the immutable 0.4.0 stable artifact.
The release source may differ from the accepted public-authority implementation
`2f11750c07317d879f1bedfd2198c36786b8ca74` in package version metadata,
release tooling, tests and documentation. The rejected first preview soak additionally
requires one explicit runtime repair: completed command watchdogs must exit rather
than retain threads/buffers until the original timeout. That exact process module is
hash-pinned by the release source validator; every other runtime/asset byte remains
unchanged. Qualify the exact Cargo-installed binary from a clean committed Git
revision before installing it under a new versioned directory. The rejected soak
remains archived and none of its resource thresholds are relaxed.

The public exec/patch paths now use the typed Rust permission authority. Safe
requires explicit grants for intrinsic risks; Trusted implicitly allows network,
shell expansion and inline scripts; Dangerous implicitly allows all eight Native
permission kinds but never disables Bubblewrap or grants workflow authority.
Explicit consent requires a form-capable modern MCP client. Legacy clients remain
unsupported for explicit permission approval; no automatic approval is introduced.

Rollout order: accepted public A4 -> clean Git install -> exact-binary public
permission suites and all-mode attestation -> required-LaTeX QC/compact regression
and copied-state compatibility -> TUI and resource qualification -> side-by-side
install -> candidate selector smoke -> stable rollback smoke -> recutover smoke ->
60-second Native-permission soak -> completion receipt. Failure after a selector
change restores both command entries and the previous deployment manifest.
Existing running sessions are not restarted; selection affects new launches only.

## Frozen A5 bounds

Use equivalent Safe/Bubblewrap configurations on stable and preview: three startup
samples, 10 warmup calls, then 60 alternating server-info/local-command calls.
Preview startup p95 must be <= max(2x stable, stable + 250 ms); request p95 must be
<= max(2x stable, stable + 10 ms). RSS must remain <= 256 MiB and at most 32 MiB
above stable; threads and file descriptors may grow by at most 2 and 8. A separate
60-second consent/execute/deny soak requires at least 100 iterations, <= 16 MiB RSS
growth, <= 2 additional threads, <= 8 additional descriptors, no remaining child
processes after work, and graceful shutdown within 8 seconds. These are bounded
non-regression checks, not a throughput/performance claim or a long-term soak.

## Compatibility limitations

Magma functional validation is blocked when the host license reports not authorised;
that outcome is not counted as a functional pass. An unexplained failure blocks
release. Static executable inspection is deliberately conservative: unparseable
nested shell syntax fails closed. Prefer explicit argv for nested shell commands.
The earlier cmd/quoting failure remains a known compatibility limitation, not a
claim of arbitrary-shell parsing support. No on-disk workflow migration is required.

The release receipt records exact hashes and the rollback entry. To use the new
selection, restart the desired MTM session after rollout; do not overwrite the
versioned stable binary or remove its rollback directory.
